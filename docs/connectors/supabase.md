# Supabase

One hosted project backs production; local development runs the same schema
through the Supabase CLI stack. The client singleton, the auth session and the
capability flags (`canWrite`, `canAgent`, `isServiceAccount`) are owned by
`src/contexts/SupabaseProvider.tsx`.

**The access model is not here.** RLS, the authoring RPC surface, the write
wrappers, the `semantic_search` schema and the migration workflow are
[engineering/access-and-security.md](../engineering/access-and-security.md),
which is the single owner. This doc covers the *boundary*: what crosses it, and
what a change on one side obliges on the other.

## What crosses

| Artefact | Direction | Owner |
|---|---|---|
| `supabase/migrations/**` | app → database, append-only | this repo |
| `src/types/database.ts` | database → app, **generated** | `npm run supabase:types` |
| `supabase/schema.reference.sql` | database → app, a snapshot for reading | regenerated by hand; the migrations are the truth |
| `src/lib/blueprintContract.ts` | app → the bot | this repo — see [plus-uno](plus-uno.md) |

The generated file is generated. `src/types/database.ts` is rewritten wholesale
by the CLI; editing it by hand is a change the next regeneration silently
reverts, and the revert will present as a type error in unrelated code.

## What a schema change obliges

1. A new migration. Never edit an applied one — an undo is a **new** migration.
2. `npm run supabase:types`, committed in the same change.
3. Every hand-written mapper that selects the touched columns.
   `normalizeBlueprint.ts` is the one that bites: it must carry every selected
   column, and a column it does not carry is silently absent rather than a type
   error.
4. If the change touches a table, view, FK constraint name, RPC name or RPC
   parameter the bot reads, `src/lib/blueprintContract.ts` too — that file is
   the canonical copy of the cross-repo contract, and the probe that guards it
   is described in [plus-uno](plus-uno.md).

## Two things that look like bugs and are not

**PostgREST select strings quote reserved words.** A select that reads fine in
SQL can fail in an embed hint. The FK constraint names used as embed hints are
in the contract file, which calls them "the sharpest edge in the whole
contract".

**Similarity is not a confidence score.** Measured across a 26-case set,
questions with *no* answer in the blueprint scored 0.607–0.654 while genuine
hits reached down to 0.565. No threshold separates them, which is why consumers
judge by which retrievers corroborated (`matched_by`) and never by score.
