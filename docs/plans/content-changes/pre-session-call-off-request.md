## 3. Structural changes (new steps / triggers / paths)

1. **Re-title steps**: "Early call-off" → "Files call-off (12h+, auto-approved)"; "Late call-off" → "Files late call-off (<12h, immediate removal)"; "Peer support" → "Coverage via fill-in pool"; "Internal decision" → "Supervisor review (pending/excuse)". Column count unchanged.
2. **Path shape — DECIDED (Bill, 2026-08-08): split into two paths** — "Standard call-off (12h+)" happy path and "Late call-off (<12h)" exception path; Figma §5.1/§5.2 split the same way. Also add a **"Future" path** capturing planned changes (e.g. reconfirmation-driven absences once deployed, swap §5.5) per the new future-state convention.
3. **Triggers out**: "Call-off executed → Fill-in Request › session enters fill-in pool"; "Approval → students auto-reassigned (In-session roster)".
4. **Retire**: Shift Swap Google Form, supervisor email channel, tutor-initiated #shift-swap posts — all pre-2026 mechanics. Do not carry the Notion call-off page (12fb7cca…) forward as a current-state citation; it describes the retired flow (06 #2). Its "~20 call-offs/month" figure is the manual era — production runs 300–640/month.
5. `tutor_absence` manual entry is dead (no rows since Apr 2025, 09 #3) — no cell should describe supervisors manually recording absences.

## 4. Divergences & open questions (things Bill must decide)

- **<12h call-offs are not a waiting state**: the tutor is removed from the roster immediately; approval decides excused/unexcused only (:156-158). The blueprint must not show a pending-while-assigned state for late call-offs.
- **Reconfirm-Unavailable (resolved, Bill 2026-08-08)**: reconfirmation only fires on supervisor-initiated session changes (edit/revert with notify), so declining is not a call-off by design — no call-off record is correct. Capture in the Future path as "session changed → tutor reconfirms or is released", not as a gap.
- **Excused/unexcused consequences**: what an unexcused decision actually means for the tutor (standing, hours, warnings) is written nowhere — the attendance/call-off policy Notion page is empty. Cells can describe the mechanism but not the stakes until that policy exists.
- **Swap (§5.5)** is explicitly TBD in Figma — include as a "planned" cell or omit.
- **No un-call-off after approval**: the old Notion page noted no un-call-off path; in-app, withdrawal only works while PENDING and slots remain. Confirm this is the intended final behavior before writing it as policy.
